    16→### What Was Built
    17→
    18→#### 1. compliance-rules.yaml — Config-Driven Severity Taxonomy
    19→- 7 rules across 5 categories (secrets, data_protection, network, dependencies, audit)
    20→- Each rule has: id, name, category, tier (BLOCKING/WARNING/INFO), detector type, framework citations, suggested_fix
    21→- 3 framework mappings per rule: SOC2, GDPR, HIPAA with control IDs and names
    22→- Network allowlist for outbound HTTP detection
    23→- Tier definitions with GitHub check_conclusion mapping (failure/neutral)
    24→
    25→#### 2. Rule Engine (src/lib/rule-engine/)
    26→- **types.ts**: ActionTier, RuleConfig, ComplianceRulesConfig, DiffFile, DiffHunk, DiffLine, RuleFinding, AnalysisResult, Detector interface
    27→- **config-loader.ts**: Loads/validates YAML, exports loadRulesConfig(), getRulesByTier(), getRuleById()
    28→- **diff-parser.ts**: Unified diff parser → DiffFile[] with typed lines and line numbers
    29→- **engine.ts**: analyzeDiff() orchestrator — parses diff, runs detectors, builds summary, sets check_conclusion
    30→
    31→#### 3. Detectors (src/lib/rule-engine/detectors/)
    32→- **secret-regex-detector.ts**: Regex-based secret detection, skips comments/tests
    33→- **pii-field-detector.ts**: Detects PII fields without encryption annotations (±2 line check)
    34→- **outbound-http-detector.ts**: Extracts domains from HTTP calls, checks against allowlist (wildcard support)
    35→- **index.ts**: Detector registry + getDetector() lookup
    36→
    37→#### 4. API Endpoints
    38→- **POST /api/analyze-diff**: Takes diff text, runs rule engine, persists AnalysisRun + Finding + ComplianceMapping + EvidenceRecord
    39→- **GET /api/rules-config**: Returns parsed compliance-rules.yaml grouped by tier
    40→
    41→#### 5. Diff Analyzer UI (DiffAnalyzerView.tsx)
    42→- Resizable two-panel layout: diff textarea (left) + results (right)
    43→- Summary card with BLOCKING/WARNING/INFO counts
    44→- Check conclusion banner: ✅ PASS or ❌ FAIL
    45→- Finding cards with: tier badge, rule ID, file:line, matched content, explanation, fix, framework citations
    46→- Pre-filled demo diff for immediate testing
    47→
    48→#### 6. Enhanced RulesView
    49→- Dual-tab layout: "Active Rules" (original DB rules) + "Severity Configuration" (YAML-driven)
    50→- Severity Config tab: summary bar, tier legend, rules grouped by tier with collapsible suggested fixes
    51→- Framework citation pills (e.g., "SOC2 CC6.1 — Logical and Physical Access Controls")
    52→- Collapsible YAML source viewer
    53→
    54→#### 7. GitHub Action Scaffolding (github-action/)

    56→- src/index.ts: Complete flow — reads inputs → loads YAML → runs engine → creates GitHub Check → posts inline comments → sets outputs
    57→- package.json + tsconfig.json

  1766→## Task 1a/1d: Core Rule Engine + Detectors + API + Tests
  1767→
  1768→**Date**: 2025-08-20
  1769→
  1770→### Summary
  1771→Built the complete rule engine backend for DriftFix: config loader, unified diff parser, three detectors (secret regex, PII field, outbound HTTP), engine orchestrator, two API endpoints, and a comprehensive test suite. All 8 tests pass, lint is clean.
  1772→
  1773→### Files Created
  1774→
  1775→1. **`src/lib/rule-engine/config-loader.ts`** — Loads and validates `compliance-rules.yaml`. Handles YAML quirks: sanitizes invalid backtick escapes, normalizes double-escaped regex metacharacters (`\\w` → `\w`), and validates structure.
  1776→
  1777→2. **`src/lib/rule-engine/diff-parser.ts`** — Parses unified diff format (git diff output) into structured `DiffFile[]`. Handles `diff --git`, `--- a/`, `+++ b/`, `@@` hunk headers, context/add/remove lines with correct line number tracking. Handles binary files and rename-only diffs.
  1778→
  1779→3. **`src/lib/rule-engine/detectors/secret-regex-detector.ts`** — Implements `secret_regex` detector. Runs rule patterns against `add` lines, skipping comments and test/mock files. Strips `(?i)` inline flags (not supported in JS RegExp) and gracefully handles invalid patterns.
  1780→
  1781→4. **`src/lib/rule-engine/detectors/pii-field-detector.ts`** — Implements `pii_field` detector. Detects PII field names in add lines, checks ±2 surrounding lines for encryption annotations. Flags unencrypted PII fields.
  1782→
  1783→5. **`src/lib/rule-engine/detectors/outbound-http-detector.ts`** — Implements `outbound_http` detector. Extracts domains from `fetch()`, `axios()`, `http.*()` calls, checks against network allowlist (supports wildcards like `*.auth0.com`). Flags unauthorized domains.
  1784→
  1785→6. **`src/lib/rule-engine/detectors/index.ts`** — Detector registry mapping name → instance, with `getDetector()` lookup.
  1786→
  1787→7. **`src/lib/rule-engine/engine.ts`** — Main `analyzeDiff()` function. Parses diff, iterates files × rules, runs matching detectors, builds summary with tier counts, sets `check_conclusion` based on BLOCKING findings.
  1788→
  1789→8. **`src/app/api/analyze-diff/route.ts`** — POST endpoint accepting `{ diff, framework? }`. Runs analysis, persists `AnalysisRun`, `Finding`, `ComplianceMapping`, and `EvidenceRecord` to the database.
  1790→
  1791→9. **`src/app/api/rules-config/route.ts`** — GET endpoint returning parsed config and rules grouped by tier.
  1792→
  1793→10. **`src/lib/rule-engine/__tests__/fixtures/sample-diff.ts`** — Test fixture data (SECRET_DIFF, PII_DIFF, OUTBOUND_HTTP_DIFF, CLEAN_DIFF).
  1794→
  1795→11. **`src/lib/rule-engine/__tests__/engine.test.ts`** — 8 test cases covering: diff parsing, secret detection, PII detection, outbound HTTP allowlisting, clean diffs, full engine summary, check_conclusion logic.

  1797→### Key Design Decisions
  1798→- YAML `\`` escape incompatibility handled via pre-processing sanitization
  1799→- Double-escaped regex metacharacters (`\\w`) normalized to `\w` post-parse
  1800→- `(?i)` inline flags stripped since JS RegExp uses constructor flags
