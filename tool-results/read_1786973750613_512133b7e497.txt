    67→    67→# 2. THE CORE PROBLEM
    68→    68→
    69→    69→Software teams often discover compliance and security problems AFTER code has already shipped.
    70→    70→
    71→    71→Examples:
    72→    72→
    73→    73→- personally identifiable information is written to logs
    74→    74→- secrets are accidentally committed
    75→    75→- insecure CORS configuration is introduced
    76→    76→- authentication controls are weakened
    77→    77→- encryption is missing
    78→    78→- rate limiting disappears
    79→    79→- sensitive data is sent to third-party services
    80→    80→- security controls are removed during refactoring
    81→    81→- compliance evidence is scattered across GitHub, cloud dashboards, tickets, and documents
    82→    82→
    83→    83→Traditional compliance tools often focus on periodic audits.
    84→    84→
    85→    85→DriftGuard moves compliance into the development workflow.
    86→    86→
    87→    87→Instead of:
    88→    88→
    89→    89→CODE → DEPLOY → AUDIT → DISCOVER PROBLEM
    90→    90→
    91→    91→DriftGuard creates:
    92→    92→
    93→    93→CODE CHANGE → ANALYZE → EXPLAIN → REMEDIATE → APPROVE → DEPLOY → EVIDENCE

   137→   137→

   147→   147→

   151→   151→4. The system maps the finding to relevant controls.
   152→   152→5. The dashboard updates.
   153→   153→6. A GitHub PR comment is posted.
   154→   154→7. The finding receives a severity score.
   155→   155→8. A remediation recommendation is generated.

   157→   157→10. The compliance ledger records the event.
   158→   158→11. The compliance score changes.
